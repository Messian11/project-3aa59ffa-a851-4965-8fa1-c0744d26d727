## Подход: локальный CMS на JSON-файлах

Раз Lovable Cloud не используем — контент храним в **JSON-файлах в репозитории** (`src/content/*.json`). Это даёт:

- полный контроль, никаких внешних сервисов и БД
- версионирование через git (любую правку можно откатить)
- быстрый SSR (данные импортируются в build-time)
- бесплатно, без логинов и RLS

Минус честно: «админка в браузере с кнопкой Сохранить» в чистом виде невозможна без бэкенда. Поэтому делаю **два уровня управления**:

1. **Контент-файлы + подробная инструкция** — основной способ. Менеджер правит JSON/MD через любой редактор (VS Code, или прямо на GitHub в браузере) и коммитит — сайт пересобирается.
2. **Локальная dev-админка `/admin`** — визуальный редактор форм, который читает JSON и при сохранении показывает готовый патч / даёт скачать обновлённый файл. Работает только в dev-режиме на машине редактора, на проде её нет. Это даёт удобный UX без сервера.

## Слой данных

`src/content/index.ts` — единая точка:
```ts
import { getAllMfo, getMfoBySlug, getCities, getPosts, ... } from "@/content";
```
Под капотом — `import.meta.glob('./mfo/*.json', { eager: true })`. Все страницы (`mfo.index`, `mfo.$slug`, `goroda.$slug`, `situations.$slug`, `summa.$slug`, `blog.*`, `search`) переписываю на этот источник. Хардкод из компонентов уезжает.

Search/filters/pagination на `/search` остаются клиентскими — фильтруют уже загруженный массив.

## Локальная dev-админка `/admin`

Доступна только когда `import.meta.env.DEV === true`. На продакшен-сборке роуты `/admin/*` физически не включаются (условный экспорт + редирект). Никакой авторизации не нужно — это локальный инструмент редактора.

Экраны:
```text
/admin                     — дашборд: счётчики (МФО / городов / статей), последние изменённые
/admin/mfo                 — таблица карточек: поиск, статус, сортировка
/admin/mfo/new             — форма создания
/admin/mfo/:slug           — форма редактирования (вкладки: Основное / Условия / SEO)
/admin/cities              — список + редактор
/admin/situations          — список + редактор
/admin/sums                — список + редактор
/admin/blog                — список статей
/admin/blog/:slug          — MD-редактор с превью и frontmatter-формой
/admin/settings            — site.json: меню, контакты, футер
/admin/redirects           — таблица редиректов
/admin/faq                 — FAQ-редактор
```

Кнопки сохранения в админке делают одно из двух (на выбор редактора в каждом экране):
- **«Скачать обновлённый файл»** — формирует JSON/MD и отдаёт через blob-download. Редактор кладёт его в `src/content/...` и коммитит.
- **«Скопировать diff»** — показывает изменения в виде патча (для PR на GitHub).

Это честно даёт UX редактирования через формы без бэкенда.

## Картинки и логотипы

Кладём в `public/logos/`, `public/blog/`, `public/cities/`. В JSON указываем путь `/logos/zaymer.svg`. В админке — поле «путь к файлу» + подсказка «положи файл в public/logos/». Авто-загрузки на сервер нет (её негде хранить без бэкенда).

## Тестирование (чтобы без багов)

- Smoke-тест: открываю каждую публичную страницу — отдаёт контент.
- 404 на несуществующих slug.
- Поиск + фильтры + пагинация работают на сидовых данных.
- Mobile 375px на всех страницах + админке.
- Production-сборка: проверяю, что `/admin` недоступна (404) и не попала в бандл.
- Type-check проходит, рантайм-ошибок в консоли нет.

## Финальный архив

`/mnt/documents/site-final.zip` содержит:
- весь исходный код (`src/`, `public/`, `package.json`, конфиги)
- наполненный `src/content/` со всеми текущими данными
- `ADMIN_GUIDE.md` — подробная инструкция: установка, запуск dev, как добавить МФО (3 способа: через админку, через VS Code, через GitHub-веб), как написать статью, frontmatter-поля, как добавить картинку, как добавить город / ситуацию / сумму, как настроить меню и футер, как опубликовать/скрыть запись, как откатить изменение через git, как задеплоить на Vercel/Netlify/любой статический хост, FAQ и типичные ошибки.
- `CONTENT_SCHEMA.md` — справочник полей для каждой сущности.

## Вопрос перед стартом

Один уточняющий вопрос — он сильно влияет на объём работы:

**Нужна ли локальная dev-админка `/admin` с формами**, или достаточно красиво организованных JSON/MD файлов + подробной инструкции по их редактированию (через VS Code или GitHub-веб)?

- **С админкой** — удобнее редактору, но это +~10 экранов с формами и ещё ~день работы.
- **Без админки** — быстрее, проще поддерживать; редактор работает в VS Code / GitHub. Файлы делаю с понятной структурой и комментариями, инструкцию пишу максимально подробно (со скринами шагов).
